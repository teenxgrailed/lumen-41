## Completed

- `PhoneTasks` (`TasksPhone.tsx`): Inbox / Today / Upcoming / All segmented control with open counts, the "Done 3 of 9 · 2 h 50 left · 1 overdue" line over a thin bar, sections as `PkSection` (each folds, Done is one shut fold at the bottom), `PkTaskRow` everywhere (swipe right = done, left = tomorrow, check, tap = task sheet), pull-down = search a title / Enter adds to today, "Move to today" on Overdue (one Undo for all), a quiet "Show N more" past 50 rows, empty lines per tab. The last tab is kept while the app stays open.
- `PhoneProjects` (`ProjectsPhone.tsx`): the list (colour tile, name, "4 open · next: …", progress ring, pull-down search), and a project's page at `/projects/[id]` (tile + name, "4 open · 2 h 50 left", bar, Add-a-task field, Overdue / Today / Upcoming / No date, Done fold, pull-down search-or-add, the ⋯ sheet with Edit project (name + colour, duplicate refused) and Delete project).
- Drag: every section is a `PkDropZone`, the list is wired with `usePkDrag` (P3); the write rule is P3's `dropPatch` (the data half of `ptkDropWrite`) fed by `ptkSpecs` / `projectSpecs` (model.ts): Overdue and Done are locked, Today / a day are timed (the gap is a time slot), Inbox / No date clear the date, a project in All sets `projectId` on the day of the row beside it.
- Pure model (`model.ts`): tab sections, header numbers, zone specs, project rows, pull-down hits, Delete line and snack. Reuses `work/model.ts` (isOverdue, byTime, byDay, projectGroups, projectStats, nameTaken, upcomingTitle).
- `?task=<id>` (`TaskParam.tsx`): opens the phone task sheet once and cleans the URL (links to `/tasks?task=…` still work on the phone).
- The route components choose the face: `WorkScreen` returns `PhoneTasks` / `PhoneProjects` when `usePhoneUi() === "phone"`, else the desktop `WorkScreenContent` exactly as before (flag off still returns null before this branch). Loading / offline / error / no-access are the states layer's `StScreen`.
- Writes: `useUpdateTask` (done, tomorrow via `laterPatch`, reopen, moves), `useCreateTask` (pull-down add = `createDraft` today; page add = undated task of the project), `useUpdateProject` (Edit), `useArchiveProject` (Delete). Every write has Undo through `snack()` (`notify`).
- CSS (P6 section, motion.css): `.ptk-seg-btn` / `.ptk-more` 14 px → 13 px (rule 2), `.ptk-ring-fill` stops easing stroke-dashoffset (rule 12).

## Round 2

- CI failure of `projects.dom.test.ts` (3 tests: row tap, back, Add): the real cause was the kit's tap guards (`PkPullDown` click capture, `PkRow`) starting at `ended = 0`, so `performance.now() - 0 < 300` swallowed every click in the first 300 ms after the window opened. CI starts the file inside that window, my machine never did. Fixed on `port/integration` (886ab74, merged here). The tests now pin `performance.now()` to 100 (projects) and `tasks.dom` has a dedicated "tap in the first 300 ms" test; both go red with `ended: 0` restored. My earlier unreproducible local flake (first test of the file, parallel run) was this.
- Two faces, one state: `work/useWorkState.ts` is called once in `WorkScreen`, above the phone / desktop switch, and holds the selected tab, the list folds and "opened past the cap", the project page's folds and typed "Add a task" line, and the project edit sheet (which project, what was typed). Both faces read it (`WorkScreenContent`, `ProjectPage`, `ProjectSheet` take it as props; the phone face takes `state`). The remembered last tab (`phoneTab()`) only seeds the initial value on the phone.
- A swiped-away row's write is not lost on a swap: the exit is timers, so `useTaskRows` writes any exit still pending when it unmounts.
- Stays with its face on purpose: the pull-down plate and its text (kit-owned, a plate over the content), the phone's ⋯ action sheet, desktop menus. Mutations outlive the component that started them.
- Forms: edit-name error has an id, `aria-describedby`, `aria-invalid` and `role="alert"`; both inputs have `enterKeyHint="done"` and `autoComplete="off"`.
- Test: `swap.dom.test.ts` mounts the real `WorkScreen`, changes state, swaps `usePhoneUi` both ways and asserts it survived (tab, fold, typed line, half-typed edit sheet, pending write); removing the unmount flush turns it red.

## Not ported

- Manual task order: no column exists. A drop inside a list sorted by something the zone does not set (Inbox, No date, a project's undated tasks) writes nothing, so reordering there is a no-op; the row settles back where the sort puts it. Reorder is real only where the zone changes a day / hour / project. (Same gap as P3's `drop.ts` `//todo`.)
- Hold actions on a task row: the prototype's tasks rows have none (a hold = lift for drag); no `PkHold` menu was invented.
- Project icon: `Project.icon` names a glyph the port has no map for; every tile draws the folder (the desktop project page does the same, `//todo` in parts.tsx).
- "Delete project" archives (`useArchiveProject`) and does not rewrite the project's tasks (no bulk task route; same `//todo` as the desktop). The phone files a task whose project is gone under "No project" (All tab, `ptkModel`), so what the person sees matches the prototype's "N open tasks move to No project", but the tasks keep their old `projectId` until a bulk route exists.
- Create / sort projects on the phone: the prototype has none ("made on the desktop for now").
- The prototype's `pkDay.queue` offline "Checked off" entries: the hooks are the offline path now.

## Decisions and constraints

- One tree: the phone face is chosen inside `WorkScreen` with `usePhoneUi()`; crossing 700 px swaps `WorkScreenContent` for the phone face and back, the route component stays mounted.
- A project's page is the route `/projects/[id]` (already flag-gated with `notFound()`), not local state as in the prototype, so the back button, deep links and the phone menu's place highlight work.
- The task sheet opens through `usePhoneOverlays().openTask`, not `?task=` (the desktop's dialog param).
- Section keys are stable ids (`overdue`, `today`, `day-YYYY-MM-DD`, `p-<id>`, `none`), titles can change with the day.
