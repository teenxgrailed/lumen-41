## Completed

- Route: `MailFaces` (client) is what `/mail` renders under design_v3; it calls `useMailbox()` once and picks `PhoneMail` (phone) or the untouched `MailScreen` (desktop) with `usePhoneUi()`. Flag off: `MailPage` as before.
- `useMailbox` (shared controller, above the face switch): view tab, open message, "Read" fold, the threads being made into tasks (pending), and every write: mark read, archive, make task (mail as the task's origin), take the task back, add to calendar (`useCreateEvent`), mark unread, sync. One write per message at a time (`once`).
- Phone face (`phone/mail/PhoneMail.tsx`): large "Mailbox" title with a rolling "N unread" (or "All read ✓"), Sync chip, three view chips (Needs you · All · Made into tasks) with counts, day sections, rows (avatar, sender, subject, time, unread dot, Task tag), per-account "disconnected" banner with Reconnect, pull-down search, hold a row for its actions, "Read" fold when everything is read, empty states (nothing needs you / no tasks yet / inbox clear / no mail account connected -> Open Connections), loading skeleton and StError with Retry (offline text when paused).
- Swipe right = Archive (PATCH `{archive:true}` exists: Gmail/Outlook mutate at the provider, `isArchived` is stored). Swipe left = Make task for later (`useCreateTask`, `source: {kind:"mail", id}` -> Task.originKind/originId, exactly the desktop's draft); a row that already became a task has no left swipe. The gestures are PkRow's: pointercancel / abort never commit, a second pointer is ignored, listeners are removed on end and unmount.
- Reader (`PhoneThread.tsx`): sheet at 0.6 / 0.92 with sender, subject, sanitized body (`useThread`), attachment names, "As a task" line; foot: Reply (link to the message in Gmail / Outlook, `providerLink`), Make task (today / later / calendar event) or Task made (take back), and a "more" menu (Forward at the provider, Add to Calendar, mark unread/read, Archive). Opening marks it read (PATCH isRead).
- `useMailSync` (new, `hooks/mail-sync.ts`): POST /api/mail/sync, refreshes the mail list now and again after 5 s (timer cleared on unmount).
- Tests: model (pure), the face over a fake controller (swipes, cancel, second pointer, no left swipe once made, unmount mid-swipe, no send/draft/trash words, no-account state, error + Retry, Reconnect banner, Sync), the controller (origin draft, one write at a time, failed write returns the row, archive closes the open message), the face switch (state survives phone -> desktop -> phone, one mount).

## Not ported

- Compose, Reply all, Forward composer, Sent, Drafts, Trash and "Discard" (owner: mail is read-only). Reply / Forward open the provider instead.
- Hold-menu Reply / Forward: the provider link needs the message's account, which is fetched when the reader opens (`useMailRef`); they are in the reader only.
- Archive Undo: there is no un-archive on PATCH /api/mail/messages/[id] (`//todo` as on the desktop), so the notice has no Undo.
- Account filter chips: the prototype has none (only the three views); the desktop shows the accounts as labels only.
- Threads grouped by `threadId`: the desktop does not group (it lists messages, `threadId` only travels on the row), and archive / read are per message, so the phone lists messages exactly as the desktop does.

## Decisions and constraints

- PkRow takes a string `title` and `time`: the unread state is a `data-pml-unread` attribute on the hold box (heavier sender + a lavender dot before the time, P8 section in motion.css) instead of nodes in those slots; the kit is untouched.
- The StScreen layer is absolute (`inset:0`), so inside a scrolling PkScreen it would cover the title; the face uses `screenState` + `StSkeleton` + `StError` inline.
- The desktop face keeps its own tab / open message (MailScreen.tsx is untouched); crossing 700 px desktop -> phone starts on "Needs you" with the phone's state, which survives phone -> desktop -> phone. Data is shared through the query cache by key. A 6-line follow-up (optional controller props on MailScreen) would share the tab too.
- IMAP accounts: the PATCH route archives IMAP locally only (the provider mutation runs for isRead only), so a swiped-away IMAP message is archived in Needt, not at the server.
