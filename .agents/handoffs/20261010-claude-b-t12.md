## Completed

  Hide done, view/size remembered in `UserSettings.prefs`
  (`view`, `calHideDone`, `calDays`).

  "+N more at HH:MM"; peek (Open / Done for tasks, Edit title / Delete for own
  events); click-a-slot draft → event create; `/calendar?new=event`.

  `timeline`; sidebar `project` targets work too. Drop → `useUpdateTask`
  (placeAt + `isFixed`) with an Undo notice.

  point), rects cached per drag and dropped on scroll/resize/autoscroll, one
  ResizeObserver per view container. Measured in Chromium: 3–4
  getBoundingClientRect calls for a whole 30-move drag, 0 inside pointermove.
- Verified against a local Postgres + dev server with the flag override:
  Week / Agenda / 3-day in light and dark at 1440×900 and 820×900; drag Sat
  16:00 → Sun 10:15 saved `scheduledStart` 10:15 local and
  `scheduleLocked = true`.

## Open / for the integrator

- The shell should host one drag layer (App.jsx does); `V3DragProvider` is
  ready for a one-line mount in `V3Shell` (S2). Until then the calendar mounts
  its own and `useV3Drag()` picks the shell's when present.
- Undo notices go through `notify` → the corner island, which v3 does not
  mount yet (T24), so they are not visible in v3 today.
- No create-local-feed hook: creating an event with no calendar shows an
  error (//todo in CalendarCraft).
- Renaming a synced event writes the local copy only (`PATCH /api/events/[id]`
  has no provider write-back).
- `GET /api/events` has no range filter (existing //todo in hooks/events.ts).
