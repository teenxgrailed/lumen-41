## Round 2

- CI failure, real cause: the kit's pull-down (`PkPullDown`) swallowed any click inside the screen for 300 ms after `S.ended`, which started at 0, so `performance.now() < 300` (a page, or in jest a jsdom window, in its first 300 ms) ate taps. CI's warm transform cache ran the whole `docs.dom.test.ts` inside that window; a slow local run did not. Fixed on port/s1-kit-tap-guard (#113, `-Infinity`), merged here. Not time zone, fake timers or shared storage. My test `a tap in the first 300 ms of the page's life is not swallowed` mocks `performance.now` to 5 and went red against `ended: 0`, green now.
- Two faces, one controller (round 3): `useDocsController` (now `src/components/needt3/docs/useDocsController.ts`) is called once in `DocsFace` and handed to BOTH `DocsPhone` and the desktop `DocsScreen` (`ctl` prop). It owns the sort (stored in `needt.docsSort`; a blocked storage keeps the sort chosen in this visit), the desktop layout switch (grid / cards / list), the Quick Open words (phone only), and the create guard with its open-after-create follow-up, so a create started on either face is never repeated by the other. Local to a face and why nothing is lost: the phone ⋯ menu and long-press sheet (transient, no data), the pull-down plate's draft (kit-local), the Page Style / Share sheets (they close on a swap; every write is a TanStack mutation that finishes after the face is gone; Delete's follow-up leaves by the router when the phone face is gone).
- ONE editor (round 3): `DocumentFace` renders `PageWorkspace` once through `createPortal` into a host element it owns (`data-doc-editor`), outside the face switch. `DocumentScreen` and `ReaderPhone` take `editorSlot` (a callback ref) instead of `children` and draw an empty `contents` slot; a layout effect moves the host into the showing slot and sets that face's classes (the desktop's exact `[&>div]` classes, the phone's `pd-editor min-w-0`). Phone -> desktop -> phone mounts the editor once and unmounts it never (test with an instance id). The editor is mounted while the page loads or is readable, not for no-access or a failed load. Because the editor's events bubble through the portal's React parent, the reader's focus, pointerdown and click-capture listeners are native listeners on its root. The DOM node changes parent, so focus and the keyboard are lost on a swap; the editor's state and collaboration socket are not. Not verified in a browser.
- Tap guards: `useReaderSlide` `ended` starts at -Infinity (same bug class as the kit's #113); tests mock `performance.now` to 5.
- Dock vs the editor's own "Page editing actions" bar (fixed, `sm:hidden`, placed at 68 px for the old dock): menu A's pill is 64 px tall at 10 px, so it covered the bar. docs.css P7 now lifts the bar to `calc(84px + env(safe-area-inset-bottom))` inside `.pd-reader`, and onto the keyboard (`var(--pd-kb)`) while typing, when the pill is already stepped away through `usePhoneCover`. The rule lives under `.pd-reader`, so closing or unmounting the reader releases it. Checked by a CSS+DOM test, not in a browser.
- Reader menu: until `useDocAccess` has loaded (or if it fails) only Copy link is offered.
- a11y: the invite field's message has an id, `role="alert"` and `aria-describedby`; `enterKeyHint="send"`, `autoComplete="off"` on invite and Quick Open. Unmount cleanup: the ⋯ menu clears `data-pk-moving` on unmount (the host is remembered while attached), the reader clears `data-pd-sliding`.

## Not ported

- Shared tab (and so Recents / Shared tabs): the desktop port has no "shared with me" listing (data map: `GET /api/pages?shared=1` is missing; Shared is P10). The home has no tabs.
- Quick Open and the pull-down search the title only: the list API sends no block text. The card miniature shows the title only (the first blocks need a preview field on `GET /api/pages`; same `//todo` as the desktop card).
- Duplicate and Move to…: the desktop port lists both as having no v3 flow, so they stay missing (`useUpdateDoc` could patch `projectId`, but the brief says do not add what the desktop lacks). The "New from template" sheet: From template goes to `/templates` as the desktop's "+" menu does.
- Trash / hard delete, template routes: not touched (Delete is the move to Trash with Undo that the desktop has).
- The prototype's own block editor (tap a block, keyboard accessory bar Aa / + Content / ⋯, "/" and ":" popovers, selection bubble, block action bar, Remind, Link a page, Link, the simulated keyboard): it drives a block model the app does not have. The editor stays `PageWorkspace`.
- The editor's own header is hidden in the phone reader (the chrome replaces it): the save-state dot, collaborator dots and its "Page options" popover (version history, templates, comments, permissions, folder, tags, private page) have no phone entry yet. OWNER QUESTION: add a "Page options" row to ⋯, or keep the editor's header as a slim bar under the chips? The toolbar is hidden too (it was already `hidden` below 640 px).
- Page Style: Cover Art (the editor draws `coverUrl` as a picture URL; same `//todo` as the desktop), Separator Style, Text colour, Wide page (the prototype's phone sheet has none of them).
- Share: AI access per tool, "Can edit" on the link, inviting someone outside the workspace, the Publish and Export tabs (Publish is the same switch as General access) — no routes (data map M1/M2).
- The list is not kept mounted under the reader (separate routes `/pages` and `/pages/[id]`), so the prototype's parallax of the list and its shade are not drawn; the page slides over the ground.
