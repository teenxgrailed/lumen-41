## Completed

- `StGlyph` (states/StGlyph.tsx): the prototype's shared marks (cloud-off, lock, alert, refresh, check, x, ...) drawn as inline paths; unknown name -> the `fallback` icon (the phone passes info). Used by the phone Ask note.
- Sign-in on a phone (`phone/auth/PhoneAuth.tsx`): same host callbacks as the desktop `AuthScreen` (`onSubmit`, `onRecover`, `onProvider`, `notice`, `aside`), so one `V3SignInRoute` serves both; NextAuth `signIn`, `safeCallbackPath`, the register endpoint and the reset / resend endpoints are the desktop's, untouched. Only the providers the host reports are drawn. Both fields at once (the phone has no two-step), form submit on Enter, offline note, network failure with Retry that replays the last request, 429 on the reset link, recovery ask -> sent with a 30 s resend countdown.
- Closed sign-ups: `/api/auth/public-signup` is read by the host; its state is tri-state (`null` until answered). Closed -> the line "New here? Join the waitlist at needt.app" (link https://needt.app) and no "Create one"; unknown -> neither is drawn; open -> "Create one". The same line (`WAITLIST`, `showWaitlist` in auth-logic) is now on the desktop screen too: it was NOT there before (see PR note).
- Which face: `V3SignInRoute` takes `initialUi` / `uiForced` from the page (`phoneUiFrom` over the request headers and the `needt-ui` cookie, as the signed-in layout does) and resolves with `useResolvedPhoneUi`.
- Setup on a phone (`phone/auth/PhoneSetup.tsx`, `MenuStep.tsx`): five steps (use, calendar + hours + time zone, "Build your menu", first task, where it went), progress dots, a theme switch with icons, Skip. "Build your menu": three-slot pill in miniature + section tiles; tap to add / remove, drag a slot sideways to reorder (transform only, one `frameWriter` stream, `pkTrack`: a cancelled pointer never commits, a second pointerdown is ignored, listeners are removed on end and on unmount), arrow keys reorder, a full pill shakes once. Saved as `prefs.mobileTiles` in the desktop's spellings (`today` for Home), which `menuTilesFrom` (P2) reads.
- One controller for both faces: `auth/useOnboarding.ts` (extracted from the desktop `OnboardingScreen`, behaviour unchanged): no prefs write before settings load (`setPref` rejects), hours sent only when loaded and changed (`hoursPatch`), only visited steps saved (`stepsToSave`), the third step writes `mobileTiles` on the phone and `sidebarTiles` on the desktop. `OnboardingScreen` is now a wrapper that picks `PhoneSetup` or the desktop face by `usePhoneUi()`.
