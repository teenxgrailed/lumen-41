## Scope

- Owner request (2026-10-12): the phone has no real icons; use the real brand marks. Owner decision recorded in CLAUDE.md (Conventions: Brand marks).
- Spec: docs/port/prototype/brand-icons.js header ("use each brand's official brand-kit app icon"), SCREENS.md:572 and :761 (40 on desktop cards, 36 on the phone, 44 in setup / the account sheet).
- Out of scope: legacy `src/components/needt/**`, `settings/IntegrationSettings.tsx`, `AccountManager.tsx` (flag-off screens, untouched).

## Completed

- `src/components/needt3/brand/`: `BrandIcon({ id, size, title, date })`, `hasBrandIcon`, `brandIdFor` (one place: provider / toolkit / catalog slug to mark, `ids.ts`), `brandIdForConnection({kind, provider})` (Google calendar is Google Calendar, Google mail is Gmail), `brandGlyph("google"|"microsoft")` (bare mark for the sign-in buttons, shaped as an `IconType`), typed inline artwork `data.ts` (generated by `scripts/gen-brand-icons.mjs`; the app never fetches a logo at runtime). Tile: radius 22% of size, white tile for full-colour marks, the brand colour for white marks, an inset ring that reads in light and dark; fixed square; no animation. Decorative (`aria-hidden`) unless `title` is passed (then `role="img"` + `aria-label`). Ids inside a mark are scoped per instance (`useId`) so two Gemini tiles do not share a gradient.
- Apple Calendar (`ical`) is drawn in code with the weekday and the day of the month (date-utils only; re-read on focus / visibility, no timer; the server draws it blank because it does not know the person's day). The Needt API entry uses the app's own icon (`needt`). A toolkit with no mark gets a plug on the quiet tile (generic), never an invented logo.
- Used in: desktop Connections cards (`connections/ConnectionsScreen.tsx`, 40) and its two `//todo` comments / letter tile removed (the dead `.cn-tile` rule is gone from `v3-overrides/type.css`); phone Connections rows (36) and the account sheet head (44) via `phone/places/Parts.tsx` `PplTile({slug,size})`; onboarding calendar rows on the desktop (`auth/OnboardingScreen.tsx`, 32, illustration kept as the fallback) and the phone (`phone/auth/PhoneSetup.tsx`, 40); sign-in provider buttons on both faces (`auth/SignInRoute.tsx` OAUTH: Google G, Microsoft four squares; labels "Continue with Google" / "Sign in with Microsoft" from `oauthButtonLabel` in `auth-logic.ts`; the phone pair stacks in one column, rule in `v3-overrides/type.css`); phone Settings Connections row (up to three different connected apps as 24px overlapping tiles beside the count: `phone/settings/PhoneSettings.tsx`, `connectionMarks` in `model.ts`); mail account chips in the Mail header (`mail/MailScreen.tsx`, 16; an IMAP mailbox keeps its dot).

## Not ported

- Desktop Settings has no Connections count row (a text jump item), so nothing to draw there.
- Fastmail has no mark: no CC0/MIT artwork exists (Simple Icons has none; the only sets are CC BY / CC BY-SA, whose attribution would be stripped), so it takes the generic plug tile (`ids.test.ts` pins this).
- Marks are not "official brand-kit files": no kit is downloadable without per-brand terms; these are the public logo sets named in `data.ts` / the script. Replace any entry by editing its line in `scripts/gen-brand-icons.mjs` and regenerating.

## Decisions and constraints

- One mapping file (`brand/ids.ts`); callers never switch on provider names themselves.
- Brand colours are content literals in `data.ts`; `npm run tokens:check` scans stylesheets only and stays green with no allowance.
- Mono brands (GitHub, Apple, Cursor, Linear, Notion on white) sit on a tile so they read on any theme.
