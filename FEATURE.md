# Live tables — живые таблицы

Ветка: `feat/live-tables` (не в main, не в проде — продуктовый фриз до запуска на Product Hunt 17.11.2026).
Источник: задача Needt `cmwb073p100nspi0177j97d1i` «Add live tables to Needt».

## Что сделано

Claude через Needt MCP создаёт таблицу на странице и заполняет её построчно; человек с открытой
страницей видит, как сначала появляется шапка, а потом строки по одной. Колонки типизированы,
дропдауны редактируются прямо в ячейке, таблица скачивается как `.xlsx`.

**Архитектура (решение одной строкой):** таблица живёт рядом с документом страницы
(модели `LiveTable` + `LiveTableRow`), а в документе лежит только атом-блок `needtLiveTable`
с `tableId`. Причина: MCP не может писать в документ открытой страницы (`PageCollaborationActiveError`),
а строки должны приходить именно пока страница открыта.

## Как попробовать

Локально (только Docker Postgres, никаких живых БД):

```bash
npm install --legacy-peer-deps
npx prisma migrate deploy        # на локальной БД
npm run dev
```

Через MCP (Claude):

```
needt_create_table  { title: "iPhone Vocal Mics",
                      columns: [ {name:"Model"}, {name:"Price", type:"number"},
                                 {name:"Status", type:"select", options:["Брать","Альтернатива","Не брать"]},
                                 {name:"Notes"} ] }
→ { id, pageId, rowCount: 0, exportUrl }
needt_add_table_rows { tableId, rows: [ ["Shure MV88+", 149, "Брать", "USB-C"] ] }   # по 1–3 строки за вызов
needt_get_table      { id }                                                           # проверить записанное
```

Через REST: `POST /api/live-tables`, `POST /api/live-tables/:id/rows`, `PATCH|DELETE /api/live-tables/:id/rows/:rowId`,
`GET /api/live-tables/:id`, `GET /api/live-tables/:id/export` — подробно в `docs/connector-api.md`.

## Проверки

- `npm run type-check` — чисто; eslint по изменённым файлам — чисто.
- Jest: новые сьюты (schema, motion, node, service, xlsx, MCP-инструменты) + все сьюты pages/MCP — зелёные.
- E2E `tests/live-tables.spec.ts` (реальные API и локальная БД, production-сборка `next build` + `next start`) — **проходит** (13.11.2026):
  шапка видна до строк и анимируется; 6 строк, записанных по одной при открытой странице, появляются с `data-arriving`;
  смена значения дропдауна в ячейке сохраняется; неверное значение дропдауна → 400 с перечнем вариантов;
  кнопка «Export .xlsx» скачивает `iPhone-Vocal-Mics.xlsx` с шапкой, числами и list-validation.
- Независимое ревью коммита (H/M/L): найденные H и M исправлены во втором коммите (см. ниже), остальное — в «Что не сделано».
- Запуск e2e: нужен поднятый сервер; штатный `npm run test:e2e` на этом сервере не использовался — `next dev` под нагрузкой
  перезапускался по памяти. Как гонял: `next build`, `next start -p 3055`, playwright с `TEST_BASE_URL`.

Исправлено по ревью:

- MCP JSON-схема: `z.number()` без границ давал `"maximum": null`, Claude такие инструменты отвергает
  (из-за этого же сейчас выключены `needt_create_goal`/`needt_update_goal`). Фикс в общем конвертере
  `json-schema.ts` — заодно, скорее всего, чинит и goal-инструменты (не проверял на claude.ai).
- Числа: `1,234` → 1234, `1.234,50` и `1,234.50` → 1234.5.
- .xlsx: скрытый лист со списками дропдауна больше не конфликтует с таблицей «Lists».
- Если таблицу не удалось поставить на новую страницу, страница тоже удаляется.
- Правка ячейки меняет в кеше только свою ячейку; строки, ждущие своей очереди анимации, не «выпрыгивают»
  при следующей пачке; после постройки таблица опрашивается раз в 15 с.

## Открытые вопросы

1. Ставить таблицу на уже открытую страницу нельзя (ограничение пути записи документа) — Claude получает 409 с подсказкой создать таблицу на новой странице. Нужно ли разрешить вставку блока через коллаб-сервер?
2. Нет вставки таблицы руками (слэш-команда) и правки колонок из UI — нужно ли это до/после запуска?
3. Цвета вариантов дропдауна (как «Брать» зелёным в Claude Sheets) не сделаны: правило «акцент никогда не заливка» — нужна отдельная договорённость по дизайну.
4. Realtime идёт только пользователю, который пишет (канал per-user); остальные участники воркспейса видят строки через опрос/фокус окна.
5. Блок хранит только `tableId`: при копировании блока или дублировании страницы обе страницы показывают
   одну и ту же таблицу, а удаление исходной страницы удаляет таблицу у копии. Нужно ли копировать таблицу при дублировании?
6. exceljs тянет заметное дерево зависимостей (archiver и др.) — ок ли это, или собирать xlsx легче?

## Что не сделано

- Удаление таблицы целиком и изменение колонок (добавить/переименовать/сменить тип) — ни в API, ни в MCP.
- Сортировка/фильтры, формулы, «форматирование» как отдельный третий проход анимации.
- Публичные (расшаренные) страницы показывают таблицу только плашкой с названием, без строк.
- Удаление строки есть в API, но нет кнопки в UI.
- Шаблоны/дубликат страницы не копируют таблицу (блок будет ссылаться на ту же `tableId`).
- Удаление блока не удаляет саму таблицу (остаётся доступной по API/MCP, пока жива страница).
- Параллельные `needt_add_table_rows` в одну таблицу не сериализованы: позиции могут совпасть, лимит 1000 строк — превыситься.
- Длинный текст в ячейке не переносится в редакторе (ячейка — однострочное поле), в .xlsx переносится.
- Realtime-событие получает только автор записи; остальные видят строки опросом (1.2 с во время постройки, 15 с после).
- Через настоящий MCP-клиент (claude.ai) инструменты не прогонял — покрыты юнит-тестами и e2e через тот же сервис.
