# Roadmap view — проекты и агенты

Ветка `feat/roadmap-view`. **Не мержить до запуска на Product Hunt 17.11.2026** (заморозка продукта).
Источник: задача Needt `cmw51xbf006bms301huz782g7` «Roadmap view for projects and agents».

## Что сделано

Один движок и один компонент карты, два места, где карта показывается. Схема БД не менялась.

| Часть | Файл | Что делает |
|---|---|---|
| Движок | `src/lib/needt3/roadmap.ts` | Чистая функция `buildRoadmap(projectId, tasks, hubItems?)`: задачи проекта превращаются в станции, считаются состояния, порядок, линии и развилки |
| Карта | `src/components/needt3/roadmap/RoadmapMap.tsx` | Вертикальная «карта метро»: SVG-трек слева, строки-кнопки справа. Клик по станции открывает задачу |
| Projects → Roadmap | `src/app/(app)/projects/[id]/roadmap/page.tsx`, `roadmap/RoadmapScreen.tsx` | Отдельная страница `/projects/<id>/roadmap`, работает и на десктопе, и на телефоне, только чтение |
| Agents → Roadmap | `src/components/needt3/agents/RoadmapTab.tsx`, `roadmap-data.ts` | Новая вкладка «Roadmap» в Agents. Выбор проекта (сначала проекты, где работают агенты), у каждой вехи видно агента и статус hub-задачи |
| Входы | `work/ProjectPage.tsx`, `phone/tasks/ProjectsPhone.tsx`, `shell/Sidebar.tsx` | Кнопка Roadmap (иконка маршрута) в шапке проекта на десктопе и телефоне, пункт «Roadmap» в контекстном меню проекта в сайдбаре |
| Стили | `src/styles/v3-overrides/roadmap.css` | По правилам PORT.md: цвет проекта только на линии и отметках, текст 13/12 px, серые цвета со шкалы, у строк нет карточек |

### Как считаются состояния (как в скилле `needt:plan`)

- **done** — задача выполнена (✓, заливка цветом проекта);
- **blocked** — задача ждёт открытую задачу: через `dependsOnId` или строку `blocked by: A, B` в описании (✕, серый: это состояние, а не тревога);
- **current** — статус `in_progress`, максимум одна станция, при равенстве побеждает порядок на доске (● с медленной пульсацией, при `prefers-reduced-motion` пульсации нет). Остальные задачи `in_progress` показываются как «In progress» и не предлагаются как следующие;
- **next** — открыта и не заблокирована; первая такая станция помечается «Up next» и рисуется цветом проекта.

Веха — любая задача проекта, кроме повторяющихся и удалённых в корзину. Порядок — порядок создания задач, исправленный так, чтобы блокер всегда стоял раньше задачи, которая его ждёт. Если две задачи ждут одну и ту же, линия разветвляется; дополнительный блокер рисуется пунктирной дугой; связь «просто следующая по порядку» рисуется тоньше, чем реальное ожидание. Блокер из другого проекта тоже блокирует и называется в строке «Waiting on …» — и через `dependsOnId`, и по названию в `blocked by:`. Название с запятой («Pricing, tiers») сначала ищется целиком. Если в заметках циклические ссылки, карта не зависает.

Ссылка hub-задачи на веху — уже существующее поле `HubItem.taskId`, его уже отдаёт `/api/agent-hub/overview`; в тип `HubItemRow` добавлены поля `taskId` и `projectId`.

## Как попробовать

1. Открыть проект → иконка маршрута справа в шапке (или правый клик по проекту в сайдбаре → Roadmap). Либо сразу `/projects/<id>/roadmap`.
2. Чтобы появились линии: в задаче указать «Waits on» (это `dependsOnId`); дополнительные блокеры — строкой `blocked by: Название, Название` в описании. Текущая веха — статус `in_progress`.
3. Agents → вкладка **Roadmap** (нужен флаг `agent_hub`). Hub-задача с `taskId` показывает агента у вехи.

Локально (как проверял я): своя Postgres в Docker на порту 55434, `.env.local` из `.env.example` с фиктивными значениями, `npx prisma migrate deploy` только в эту базу, `next dev -p 3077`, флаги `signups_open` и `agent_hub` включены в локальной БД.

## Открытые вопросы

1. **Что считать вехой.** Сейчас вехи — все задачи проекта. В обычном проекте с 40 мелкими задачами карта получится длинной. Варианты: метка `milestone` или показывать только задачи с зависимостями — решает владелец.
2. **Правка роадмапа через Agents Chat.** Кнопка «Change in Chat» сейчас только переключает на вкладку Chat. Нужен ли готовый промпт («поменяй роадмап проекта X») и инструменты ассистента для `dependsOnId` — отдельная задача.
3. **Лог страницы плана** (`plan-page:` в описании проекта, который пишет `needt:plan`) на карте пока не показывается. Его можно вывести под картой как «последние изменения».
4. **Выбор проекта в Agents → Roadmap** не сохраняется: если уйти с вкладки и вернуться, снова выбран первый проект. Можно хранить его в `?project=`.
5. **Горизонтальная карта на широком экране.** Сделал вертикальную на обоих экранах: строки читаются как список, названия не надо сокращать. Если нужна горизонтальная «метро»-лента на десктопе — это дизайнерское решение (PORT.md).
6. **Публичный API.** Карта собирается на клиенте из `/api/tasks`. По правилу «данные доступны снаружи» стоит добавить `GET /api/projects/<id>/roadmap` (тот же `buildRoadmap` на сервере) и инструмент MCP — сейчас не сделано.

## Что не сделано

- Нет серверного эндпоинта и инструмента MCP для роадмапа (см. вопрос 6).
- Нет редактирования на самой карте: перетаскивания, изменения порядка, «Start» / «Done» прямо на станции. Всё меняется в задаче.
- Нет e2e-теста Playwright и визуального эталона для новой страницы.
- В Agents у вехи показывается только последняя hub-задача, а не все.
- Не смержено и не задеплоено (заморозка); PR не открыт.
