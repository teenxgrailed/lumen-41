# Счётчик прогресса и мини-вход (план 11: T-1, T-2, T-4)

Ветка `feat/progress-counter`. **Заморозка продукта до запуска на Product Hunt 17.11.2026:** ветку не мержить в `main` и не деплоить до этой даты. Источник: `docs/plans/11-task-model.md`.

## Что сделано

### T-1. Счётчик `0/3`

- Счётчик — это задача, у которой все подзадачи (`TaskPart`) без названия. Тип задачи, новая колонка и выбор при создании не добавлялись, как и требует план.
- Счётчик включается в диалоге задачи: меню `…` → **Count it**. Задача становится `0/3`.
- В диалоге есть строка **Count**: `N of [цель]`, кнопки `−`, `+` и `×` (убрать счётчик). Цель можно менять с 1 до 30. 30 — общий лимит подзадач `MAX_SUBTASKS`.
- В строке задачи бейдж `1/3` работает как кнопка «ещё один». Последнее нажатие закрывает задачу через обычный путь закрытия: с анимацией и одним Undo на всё.
- Счётчик не раскрывается в список шагов (`Untitled step`), ни в строке, ни в ленте проекта (`flow.ts`).
- Повторяющаяся задача со счётчиком начинает каждое новое повторение с `0/N` (`recurring-completion.ts`).
- Планировщик не трогали: одна задача — один блок.
- API:
  - `GET /api/tasks/:id/count` возвращает `{ counter, target, done }`.
  - `PUT /api/tasks/:id/count` принимает `{ target, done? }`. `target: 0` убирает счётчик.
  - Если у задачи есть именованные подзадачи, ответ — 409 `NAMED_PARTS`. Если задача в архиве или в корзине — 409 `TASK_READ_ONLY`.
  - Строки сохраняют свои id при изменении счётчика.
- При конвертации задачи-счётчика в цель безымянные части получают имена вида `Название 2/3`.

### T-2. Мини-вход (правило двух минут), ручной

- Новая колонка `Task.moveCount`, миграция `20261112230000_task_move_count`. Она только добавляет колонку: значение по умолчанию 0, без бэкфилла.
- `moveCount` растёт, когда человек переносит задачу на более поздний день в своём часовом поясе. Учитываются:
  - `PUT /api/tasks/:id` (UI);
  - `task.update` и `task.move_to_day` (MCP, Ask);
  - перенос `dueDate`, `scheduledStart` на другой день и `postponedUntil` в будущее.
- Не учитываются: смена времени внутри дня, перемещения планировщиком, закрытие задачи (включая сдвиг повторяющейся).
- После двух и более переносов, если у задачи нет `entry` и она открыта, строка **First step** в диалоге спрашивает: «Moved N times. What would take two minutes?».
- Явное действие: меню `…` → **Give me a way in** ставит курсор в поле первого шага.
- Генерацию ИИ **не делал**: в плане стоит гейт «20 реальных задач, ≥12 годных», и он не пройден.

### T-4. Группы со стоимостью

- Используются существующие поля задачи: `valueCents` (сколько просишь) и `earnedCents` (сколько пришло).
- В диалоге: меню `…` → **Add an amount** открывает две строки, **Listed** и **Received**, в CHF. Ввод принимает `1’200`, `1 200`, `1,234.50`, `1.234,50`, `CHF 80`.
- В строке задачи:
  - если деньги уже пришли — пришедшая сумма (зелёным) и рядом выставленная (тихо);
  - если ещё нет — только выставленная.
  - У рабочей задачи без суммы денежного слота нет вообще.
- В шапке проекта, если хоть одна задача несёт сумму: `CHF 180 earned · CHF 340 listed`.
  - Главное число — только реально полученные деньги.
  - `listed` — сумма по ещё не проданному.
  - Закрытая задача без введённой суммы показывается как «N sold, amount not entered». Цена из объявления не засчитывается как заработок.
  - Учитываются и задачи без слота (`noSlot`), что типично для продаж.

## Как попробовать

```bash
docker run -d --name pc-pg -e POSTGRES_USER=needt -e POSTGRES_PASSWORD=needt -e POSTGRES_DB=needt -p 127.0.0.1:55445:5432 postgres:16-alpine
cp .env.example .env   # DATABASE_URL/DIRECT_URL → postgresql://needt:needt@127.0.0.1:55445/needt
npx prisma migrate deploy && npm run dev
```

1. Создать задачу, в меню `…` выбрать **Count it** и нажать на `0/3` в строке. Третье нажатие закроет задачу.
2. Дважды перенести задачу на завтра (дата или drag), открыть её и увидеть вопрос в **First step**.
3. В проекте «Resale» добавить суммы двум задачам (**Add an amount**), у одной заполнить **Received** и посмотреть шапку проекта.

## Открытые вопросы

1. **Размер главного числа T-4.** План требует, чтобы число было «громким», но правило шкалы — только 13/12 px. Сейчас `earned` — 13 px medium в шапке. Нужен ли отдельный размер, решает владелец.
2. **Валюта** жёстко CHF, как в существующем `TaskValue`. Прототип дизайна использует €. Нужна ли настройка валюты?
3. **Отмена переноса не уменьшает `moveCount`.** Перенос → Undo → перенос считается за два. Как исправить: хранить счётчик в снапшоте отката (`task.restore`) или считать переносы по `TaskActivity`.
4. **Считать ли перенос агентом по своей инициативе** (не по просьбе человека)? Сейчас считается любой перенос через ops.
5. **Отгрузка проданной вещи** — подзадача товара или соседняя задача в группе? В плане это решается по реальным данным, здесь не решено.
6. Открытый вопрос T-1 из плана («считается ли +1 как "тронул" для закрытого дня») остаётся заблокирован на T-3.

## Что не сделано

- ИИ-генерация мини-входа: закрыто гейтом из 20 задач, нужен прогон вручную владельцем.
- Анимация продажи и связь с `budget.needt.app`.
- Телефон: на `TaskSheet` безымянные части показываются как «2 of 3». Отдельной настройки счётчика на телефоне нет: тап по бейджу в строке работает, а **Count it** есть только на десктопе.
- MCP:
  - нет инструмента для счётчика (только REST);
  - `moveCount` не входит в `taskView` у ops;
  - `complete_subtask` по названию не может выбрать безымянную часть.
- Поля **Listed/Received** в открытом диалоге не подхватывают изменения, сделанные в другом месте, пока диалог открыт.
- Через API достижение цели не закрывает задачу, как и с обычными подзадачами. В UI закрывает.
