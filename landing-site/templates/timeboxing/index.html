What’s inside

  • Box list — task, time limit, start time, and a written definition of done.
  • Stop rule — what you do when the box ends: ship it, book a second box, or drop it.
  • Review column — finished, partly, or over, plus the minutes it really took.
  • Estimate check — after a week, the gap between your boxes and reality.

Where it comes from: the term “timebox” grew up in software project management. James Martin’s Rapid Application Development (1991) is often cited for it, and agile teams use the same idea for fixed-length sprints. This template applies it to one person’s tasks. For the definition, see the timeboxing glossary entry.

When to use it (and when not)

Use timeboxing for work that expands to fill the time you give it — research, polishing, design exploration, writing first drafts. It is also good for tasks you avoid, because 25 minutes is easier to start than “finish the report.”

Do not timebox work with a hard quality bar you cannot cut, like a tax filing or a security fix. Those need an estimate, not a limit.

How to use it

  1. Write the task and the box length. 25, 45 or 90 minutes are easy to remember.
  2. Write “done when…”. A visible result: “three logo sketches photographed”, “outline with headings”.
  3. Put the box on a clock time, not just a list. A box without a start time is a wish.
  4. Work until the timer ends. Then stop, even mid-sentence.
  5. Apply the stop rule. Good enough? Ship. Not yet? Book one more box, smaller. Not worth it? Drop it.
  6. Log the review in one line. Over a week, this shows which kinds of work you underestimate.

Questions, answered.

What box length should I start with?

Pick 25 or 45 minutes for most tasks and 90 for deep work. Shorter boxes give faster feedback on your estimates.

What if I am almost done when the timer rings?

Decide on purpose. Either take five more minutes and log it as over, or stop and book a short second box. The point is that you choose.

Is timeboxing the same as Pomodoro?

No. Pomodoro uses fixed 25-minute intervals with breaks. A timebox is any length you choose for one task, with a definition of done.

How is this different from time blocking?

Time blocking assigns hours to types of work. Timeboxing caps one task. Many people use both: a deep block holding two timeboxes.

Who came up with timeboxing?

No single person. The term comes from software project management; James Martin’s Rapid Application Development (1991) is commonly cited, and agile sprints use the same idea.
