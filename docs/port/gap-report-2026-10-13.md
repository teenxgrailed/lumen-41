Method: screenshots of the same screen in both, triaged with a downscaled pixel difference, then side-by-side reads of the pairs that differ. Every visible label of the mockup (buttons, menu items, tabs, headings) was extracted from its DOM and searched for in `src/components/needt3`, `src/lib/needt3`, `src/app/(app)`. The 105 `//todo` comments in `src/components/needt3` are the app's own list of known holes and were cross-checked against the screens.

Verification tags: **[S]** seen in screenshots, **[C]** code-level only (grep or reading), **[?]** could not be verified.

Severity: **launch-blocker** (a control that does nothing, or a core flow that is missing for 2026-10-26), **visible** (a person sees it in normal use), **polish**.

### Limits of this run

- The visual user's seed data is thin (4 tasks, one doc, no projects, no habits, no boards, no mail). Most big pixel differences are the mockup's rich fixtures against the app's empty states, not layout drift. Structure (shell, sidebar, headers, toolbars, spacing, type) matches closely on every desktop screen and on the phone screens that were captured. Empty states exist and look designed on Mailbox, Habits, Templates, Moodboards, Projects (phone), Trash, Notifications.
- The Projects page and a project's own page were not captured on desktop (no seeded project). Settings sections Tasks, Focus and Connections were not captured (the click did not land); Account, General, Appearance, Your day, Notifications, Shortcuts, Plan and billing, Data and privacy, About were.
- The document editor never left its loading skeleton in this environment (`COLLABORATION_DISABLED=1`), so the real editor body, cover and block menu are **[?]**.
- Time theme depends on the clock. The mockup was re-captured with the same frozen clock (10:30), so Time compares as daytime in both.
- Phone: Light for Home, Calendar, Tasks, Mailbox, Habits, Moodboards, Projects, Templates, Shared, Connections, Docs; Dark and the rest of the phone set were not finished (the dev server restarted under load several times). Phone Trash, Settings and the menu were checked in code only.

## Theme issues

- Light and Dark: no colour or contrast defects found in the captured screens (Dark pixel differences are the same data differences as Light: Today 6.9, Tasks 5.0, Calendar 5.1, Projects 4.8, Settings 4.7, Trash 1.2).
- Time: with the frozen daytime clock, Time matches Light in both. Not checked at dusk or night.
- First paint: `DEFAULT_THEME` is `system`, the mockup's is Light. Until `useHydrateLook` receives `/api/user-settings`, a person with a Light setting and a dark OS sees dark skeletons. Persisted `needt3-ui` localStorage hides this on repeat visits.
- Dark loading skeletons flash behind overlays when the page behind is still fetching (seen under Palette and Notifications).

## Motion, empty and loading states

- Empty states are present and designed for Mailbox, Habits, Templates, Trash, Notifications, Moodboards, Projects (phone). Compare with the mockup's illustrations case by case after data exists.
- Loading: skeleton rows replace content on every screen (matches the mockup's shape only roughly; the document skeleton is a flat block).
- Motion was not compared (screenshots with reduced motion); `MOTION.md` rules (growing island, no damped spring) were not re-verified.

## Repro

Mockup: any static server on the parent folder, then `index.html?screen=<today|calendar|tasks|docs|mail|projects|moodboards|habits|templates|shared|trash|connections>&theme=<light|dark|time>`. Phone: `mobile.html?theme=light`, menu button at (282, 782).

App: `docker compose -f docker-compose.e2e.yml up -d`, `NEEDT_DESIGN=v3 npx tsx scripts/reset-e2e-environment.ts`, a dev server with the env from `tests/e2e/environment.ts` (the `NEXTAUTH_SECRET` there must match the one the visual helper signs with), then a Playwright spec that calls `signInVisualUser(page, { design: "v3" })`, sets the theme with `PATCH /api/user-settings`, and opens `/today`, `/calendar`, `/tasks`, `/pages`, `/mail`, `/projects`, `/moodboards`, `/habits`, `/templates`, `/shared`, `/trash`, `/connections`, `/settings`.
